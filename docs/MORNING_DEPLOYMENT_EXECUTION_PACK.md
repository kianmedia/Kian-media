# حزمة تنفيذ الصباح — برنامج ما بعد منصّة المشاريع

> **Push آمن قبل SQL.** كل موديول جديد يكشف غياب الترحيل ويعرض
> «الميزة بانتظار تفعيل قاعدة البيانات» بدل الانهيار. أُثبِت ببناء ناجح واختبارات خضراء.

## 1–4 · Git

| البند | القيمة |
|---|---|
| `START_HEAD` | `1f0faff` (= `origin/main` عند البداية) |
| Commits غير مرفوعة قبل الليلة | **صفر** — دفعتَ كل شيء |
| Working Tree | **نظيف** |

**Commits الليلة بالترتيب — ادفعها كلّها معًا:**

| # | SHA | المحتوى |
|---|---|---|
| 1 | `561e935` | تجميد منصّة المشاريع + نقطة الأمان |
| 2 | `c877694` | خارطة المؤجَّل |
| 3 | `a6ffd8e` | مركز الاتصالات + مركز التشغيل |
| 4 | `f610a7d` | CRM + المالية + التقارير التنفيذية |
| 5 | (هذا الملفّ) | حزمة التنفيذ |

```bash
git push origin main
```

**ثم انتظر Vercel = Ready، وافتح البوابة وسجّل الدخول قبل تشغيل أيّ SQL.**
هذا يُثبت أن Feature Detection يحمي الموقع في الفترة بين النشر والترحيل.
انكسار صفحة هنا خللٌ في الكود، وعلاجه ليس تعجيل الترحيل.

## 6–7 · ملفّات SQL — خمس حزم مستقلّة، بالترتيب

**كل حزمة مستقلّة. لا تدمجها في ملفّ واحد.**

| الترتيب | الحزمة | الملفّات |
|---|---|---|
| **1** | مركز الاتصالات | `communications_hub_{PREFLIGHT,RUNME,POSTCHECK}.sql` |
| **2** | مركز التشغيل | `operations_center_{PREFLIGHT,RUNME,POSTCHECK}.sql` |
| **3** | CRM | `crm_sales_FOUNDATION_{PREFLIGHT,RUNME,POSTCHECK}.sql` |
| **4** | المالية | `finance_profitability_{PREFLIGHT,RUNME,POSTCHECK}.sql` |
| **5** | التقارير التنفيذية | `executive_reporting_{PREFLIGHT,RUNME,POSTCHECK}.sql` |

**داخل كل حزمة:** `PREFLIGHT` (قراءة) ← `RUNME` (تغيير) ← `POSTCHECK` (قراءة).
**اقرأ نتيجة PREFLIGHT قبل RUNME. لا تتخطَّه.**

### 8–10 · النتائج المتوقَّعة

- **PREFLIGHT** — قراءة فقط، يخبرك بما هو موجود وما سيتغيّر. لا ERROR.
- **RUNME** — ينتهي بـ`Success` وإشعار `SELF-TEST: PASS`. داخل `begin … commit`،
  فالفشل تراجع ذاتيّ كامل بلا حالة نصفيّة.
- **POSTCHECK** — قراءة فقط، كل استعلام بنتيجته المتوقّعة، وبوّابة ترفع ERROR على
  الفشل الحقيقيّ وحده.

> ⚠️ **ظهرت `raise exception`؟ لا تُعِد التشغيل.** الرسالة تقول ما لم يتحقّق.
> أرسلها لي حرفيًّا. والملفّ داخل معاملة، فلا شيء تغيّر.

## 12 · الاعتماديات

- الحزم 1–4 **مستقلّة** عن بعضها. الترتيب أعلاه للراحة لا للإلزام.
- **الحزمة 5 (التقارير) تُشغَّل أخيرًا**: تقرأ من الأربع السابقة. لو شُغِّلت قبلها
  فلن تنكسر — ستعرض مؤشّراتها **«غير متاح»** مع السبب، لا صفرًا.
- لا شيء منها يعتمد على منصّة المشاريع، ولا يعدّلها.

## 13 · هل Push قبل SQL آمن؟ **نعم**

كل سطح جديد يُصنّف `PGRST202/204/205/42703/42P01` ويعرض «الميزة بانتظار تفعيل
قاعدة البيانات». لا شاشة بيضاء ولا استثناء غير مُلتقَط. البناء ناجح والاختبارات
خضراء على الكود وحده.

## 14 · Feature Flags

قنوات الاتصالات تُنشأ **مُطفأة** و`dry_run = true`، والترحيل **يرفض** غير ذلك.
⇒ حتى بعد تشغيل SQL **لن يُرسَل شيء** حتى تُفعّل القناة بقرارك.

## 16 · اختبار الإنتاج لكل موديول

| الموديول | الاختبار الحاسم |
|---|---|
| الاتصالات | أنشئ حدثًا ⇒ يدخل الطابور بحالة `queued` و**لا يُرسَل شيء** (القناة مُطفأة) |
| التشغيل | أنشئ مهمّة وأسند طاقمًا ⇒ التعارض يُكتشف · الطاقم يرى مهمّته فقط |
| CRM | موظّف مبيعات يرى فرصه فقط · **لا يرى عمولة غيره** · لا يعدّل هدفه |
| المالية | موظّف وعميل **يُمنعان من كل مسار ماليّ** — جرّبه بعينك في نافذة خاصّة |
| التقارير | المؤشّرات الحسّاسة للمالك وحده · «غير متاح» لا صفر |

**الأهمّ:** افتح حساب **عميل** في نافذة خاصّة وتأكّد أنه لا يرى: التكلفة · الهامش ·
الربحية · العمولات · مركز التشغيل · طلبات الاتصالات الداخلية.

## 17 · حدود معروفة — مذكورة لا مخفيّة

1. **البريد لم يعمل قطّ** (Apps Script). موثّق في `NOTIFICATIONS_CURRENT_STATE_AUDIT.md`
   مع ترتيب مخاطر الإرسال المزدوج. **لم يُصلَح الليلة** — المسار القديم خارج النطاق
   وتغييره على غير هدى هو ما يصنع الإرسال المزدوج.
2. **`lib/portal/notifyEmail.ts:57`** يُطلق طلب `no-cors` من المتصفّح، ومنه صفحة
   الفرص **العامّة**. مرصود ولم يُمَسّ.
3. **متبقٍّ ماليّ مقبول:** حامل `finance_ops.view` يرى `fin_receivables.amount_net`
   (إيراد مُفوتَر) و`fin_costs`، فيستطيع طرحهما للوصول إلى هامش **تقريبيّ** دون
   `view_profit`. تضييق الذمم كان سيكسر التحصيل. مذكور في `FINANCE_ROLE_MATRIX.md` §11.
   القيمة التعاقدية والإيراد المعترَف به والاحتفاظات والهوامش الدقيقة تبقى خلف البوّابة.
4. لم تُختبر RLS حقيقية ولا PostgREST حيّ — الاختبارات تُنفّذ منطق الدوالّ لا فرضَ
   قاعدة البيانات له.
