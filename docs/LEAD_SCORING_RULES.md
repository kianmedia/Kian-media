# قواعد تقييم العملاء المحتملين — V1

> **المصدر الوحيد للحقيقة هو قاعدة البيانات، لا هذا الملفّ.**
> القواعد صفوف في `public.lsr_rules`، والعتبات صفوف في `public.lsr_settings`.
> هذا المستند يشرح **الآلية** ويسرد البذور الأولى؛ فإن اختلف عن القاعدة فالقاعدة
> هي الصحيحة، وهذا الملفّ هو المتأخّر.

الحزمة: `docs/lead_scoring_routing_{PREFLIGHT,RUNME,POSTCHECK,ROLLBACK}.sql`

---

## ١) المبدأ

الدرجة **مجموع نقاط قواعد مطابقة**. لا نموذج، ولا ذكاء اصطناعيّ، ولا وزن مخفيّ،
ولا نداء خارجيّ. أيّ إنسان يستطيع أن يأخذ صفّ العميل وقائمة القواعد ويعيد حساب
الدرجة بيده ويصل إلى الرقم نفسه. هذا شرط قَبول لا ميزة إضافية: درجة لا يستطيع
مدير المبيعات أن يشرحها لموظّفه هي درجة لا تصلح لاتّخاذ قرار.

```
الدرجة = Σ (نقاط كلّ قاعدة مطابقة)  +  التعديل اليدويّ المعلَن
         ثمّ الحصر بين ٠ و١٠٠
         فإن وُجد تجاوز يدويّ، حلّ محلّ الناتج كلّه وظهر بسببه
```

## ٢) ⛔ ما لا يدخل الحساب أبدًا

**الجنس · العمر · الجنسية · العِرق · الدين · الحالة الاجتماعية · تاريخ الميلاد.**

هذه درجة تجارية عن **فرصة**، لا حكم على **إنسان**. والمنع ليس نيّة:

| الطبقة | الحارس |
|---|---|
| قاعدة البيانات | قيد `lsr_factor_no_sensitive_attribute` على `lsr_factors` يرفض المفتاح عند الإدراج |
| الترحيلة | فحص ذاتيّ في `RUNME §14` يقرأ تعريف دوالّ التقييم ويُسقط الترحيلة إن ظهر رمز ممنوع |
| بعد التطبيق | صفّان في `POSTCHECK` (٣٠ و٣١) |
| المستودع | `tests/lead_scoring_forbidden_inputs.test.js` يفشل باسم الملفّ والرمز |

القاعدة لا تستطيع الإشارة إلى عامل غير مسجَّل في `lsr_factors` (مفتاح أجنبيّ)،
وعامل ممنوع لا يمكن تسجيله أصلًا. لا يوجد باب خلفيّ.

### العوامل المشتقّة — كيف تُحسب بالضبط

- **اكتمال البيانات**: أربعة عشر بندًا (بريد · هاتف · شركة · مدينة · ميزانية ·
  صلاحية القرار · مستوى الحاجة · الإطار الزمنيّ · نوع الجهة · نوع الخدمة ·
  الاستعجال · مدّة التسليم · القيمة السنوية · التعقيد) → النسبة المئوية.
- **سلوك الاستجابة**: من `crm_activities.direction` و`occurred_at`:
  `no_contact` (لا نشاط) · `responsive` (ردّ وارد خلال `responsive_days`) ·
  `slow` (ردّ وارد أقدم) · `unresponsive` (`unresponsive_attempts` محاولات صادرة
  بلا ردّ) · `awaiting_first_reply`.
- **عميل حاليّ**: مرجع صريح فقط. **لا مطابقة أسماء** — التطابق النصّيّ يُنتج
  ادّعاءً لا معلومة.

## ٧) مخرَج التقييم

`lsr_score(lead_id)` يُرجع — لكلّ استدعاء — ما يلي:

| الحقل | المعنى |
|---|---|
| `score` · `grade` | الرقم والتصنيف |
| `grade_thresholds` | العتبات المستعملة الآن |
| `ruleset_version` | ★ إصدار القواعد الذي أنتج هذا الرقم |
| `components[]` | **كلّ** قاعدة: مفتاحها، نقاطها، هل طابقت، والقيمة المرصودة |
| `positive_factors[]` · `negative_factors[]` | ما رفع وما خفض |
| `missing_information[]` | العوامل المطلوبة الغائبة بأسمائها |
| `recommended_next_action` | إجراء واحد بقاعدة معلنة |
| `review_required` + `review_reasons[]` | هل يحتاج تدخّل إنسان ولماذا |
| `explain` | جملة تشرح المعادلة نفسها |

### الإجراء التالي — القاعدة كاملة

1. بلا قناة تواصل → `collect_contact_channel`
2. معلومات مطلوبة ناقصة → `complete_qualification`
3. فئة A وبلا مالك → `assign_now`
4. فئة A → `contact_within_24h`
5. فئة B → `schedule_discovery`
6. فئة C → `nurture`
7. فئة D → `low_priority`

### متى يُرفع علم المراجعة

- لا بريد ولا هاتف (`anonymous_no_contact_channel`)
- الاكتمال دون `review_min_completeness` (افتراضيًّا ٥٠٪)
- عامل مطلوب غائب
- تجاوز يدويّ فعّال

## ٨) التعديل اليدويّ

نوعان، وكلاهما **يشترط سببًا مكتوبًا بقيد على مستوى الجدول** لا بفحص واجهة:

| النوع | العمود | القيد |
|---|---|---|
| تعديل بالنقاط (`-40..+40`) | `adjust_points` | `lsr_manual_adjust_reason` |
| تجاوز كامل (`0..100`) | `override_score` | `lsr_manual_override_reason` |

كلّ تعديل يكتب صفًّا في `lsr_audit` يحمل الفاعل والسبب و**الدرجة قبله وبعده**.
والتجاوز يرفع `review_required` تلقائيًّا: رقم كتبه إنسان يبقى تحت النظر.

الصلاحية: `lead.override_score` أو `crm.manage_scoring` أو دور المالك — مفتاح
مستقلّ عن مجرّد رؤية الدرجة.

## ٩) تغيير القواعد — الإصدارية

```
lsr_ruleset_clone()  →  مسوّدة جديدة تنسخ المنشور
lsr_rule_upsert()    →  تحرير المسوّدة وحدها
lsr_ruleset_publish()→  نشر: المسوّدة تصير المنشورة، والقديمة تصير retired
```

**المنشور لا يُعدَّل.** مُشغِّل `lsr_rules_frozen_trg` يرفض أيّ إدراج أو تحديث أو
حذف على قواعد مجموعة منشورة. السبب مباشر: لو تغيّرت قواعد إصدار منشور، لصارت كلّ
درجة سُجّلت تاريخيًّا بذلك الإصدار **بلا معنى**، ولانهار أثر التدقيق كلّه.

الصلاحية: `lead.manage_scoring` أو `crm.manage_scoring` أو المالك.

## ١٠) الحدود

- التقييم يُحسب **عند الطلب** ولا يُخزَّن. المخزَّن هو المدخلات والتعديل اليدويّ
  فقط. تغيير قاعدة يغيّر درجة الجميع فورًا — وهذا مقصود.
- `lsr_score_scan` مسح مقصوص بسقف معلن (`score_scan_limit`, افتراضيًّا ٣٠٠)
  ويُعيد `truncated` صراحةً. **`truncated = true` تعني «لم يُقيَّم» لا «غير
  مؤهّل».**
- بلا مجموعة قواعد منشورة لا تُنتَج درجة إطلاقًا (`no_published_ruleset`)، ولا
  يُعرض صفر. الصفر المُختلَق أسوأ من الامتناع.
