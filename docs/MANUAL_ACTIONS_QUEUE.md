## مفتوح

### 🔴 M-000 — `git push origin main` (إجراء دائم بعد كل دفعة)
- **المرحلة:** كل المراحل
- **لماذا أنا عاجز:** لا توجد بيانات اعتماد Git في هذه البيئة.
  الدليل: `git push --dry-run origin main` → `fatal: could not read Username for 'https://github.com': Device not configured`.
- **الأثر:** أُنشئ Commits نظيفة ومستقلة محليًا، لكن **لا أستطيع دفعها ولا نشرها**.
  لذلك لن أدّعي أبدًا أن شيئًا «منشور» ما لم أُثبته بترويسة حيّة أو استجابة API من الإنتاج.
- **الخطوات:** افتح GitHub Desktop → Push origin. (أو `git push origin main` من طرفية لديها بيانات الاعتماد.)
- **Commits بانتظار الدفع:** انظر الجدول أسفل هذا القسم — يُحدَّث بعد كل Commit.

### 🟡 M-001 — اختبار تسجيل حضور موظف من الجوال
- **المرحلة:** P0
- **لماذا أنا عاجز:** يحتاج تسجيل دخول موظف، ولا أملك بيانات دخول.
- **السياق:** في Phase 2 غيّرتُ `Permissions-Policy`. القيمة `geolocation=()` كانت ستوقف كل تسجيلات الحضور
  (`lib/portal/hr.ts` → `getPositionOnce()`؛ وكل مستدعٍ في `components/portal/hr/EmployeeHome.tsx` يتوقف عند الفشل).
  أصلحتُها إلى `geolocation=(self)` و**أكّدتُ الترويسة حيّة على الإنتاج** — لكنّي لم أشاهد تسجيل حضور ينجح فعليًا.
- **الخطوات:** افتح البوابة على الجوال بحساب موظف → تسجيل حضور → تأكّد من عدم ظهور خطأ الموقع الجغرافي.
- **الوقت المتوقع:** 30 ثانية.
- **معيار النجاح:** يُسجَّل الحضور ويُحفظ الموقع.

### 🟡 M-002 — نشر Google Apps Script Handler
- **المرحلة:** P1
- **لماذا أنا عاجز:** لا مصادقة `clasp`، والسكربت في حساب Google الخاص بك — لا يمكن الوصول إليه من المستودع.
- **السياق:** هذا هو **السبب الجذري** لعدم وصول بريد البوابة (انظر `docs/EMAIL_FIX_RUNBOOK_batch11.md`).
- **الخطوات:** ستُكتب بالتفصيل في `docs/APPS_SCRIPT_DEPLOYMENT_RUNBOOK.md` عند إنجاز P1.
- **الأثر ما دام مفتوحًا:** تبقى P1 بحالة `READY — MANUAL DEPLOYMENT REQUIRED` ولا تُوصف بأنها Live.

### 🟡 M-003 — تسجيل MFA لحساب المالك
- **المرحلة:** P2
- **لماذا أنا عاجز:** يتطلب مسح QR بجهازك وإدخال رمز TOTP.
- **قاعدة السلامة:** يبقى `MFA_ENFORCEMENT_MODE=enrollment` حتى تُكمل التسجيل بنجاح.
  **لن أفعّل `enforced` تلقائيًا** — خطر إقفال المالك خارج النظام.
