# OBSERVABILITY — رصد الأخطاء والتوفّر

> **Wave 0 · V2-0.5-B** · مرافق: `lib/observability.ts`

## ١. الحالة بصدق

| البند | قبل Wave 0 | بعد Wave 0 |
|---|---|---|
| `@sentry/nextjs` | ❌ غير مثبَّت | ❌ **ما زال غير مثبَّت** — انظر §٢ |
| `SENTRY_DSN` | ❌ لا وجود له في الكود | ✅ مُعرَّف في `.env.example`، ويقرأه `lib/observability.ts` |
| واجهة رصد موحّدة | ❌ لا شيء | ✅ `lib/observability.ts` — بلا اعتماديات، تُنقّح، ولا ترمي أبدًا |
| مراقب توفّر | ❌ لا شيء | ⏳ خطوة يدوية — §٤ |

🔴 **لا تقل «Sentry يعمل».** اليوم: `captureError()` تُخرج **سطرًا واحدًا منظَّمًا
ومُنقَّحًا** إلى سجلّ Vercel، ويحمل `transport: "none"`. هذا أفضل من لا شيء، وليس
تتبّع أخطاء.

## ٢. لماذا لم تُثبَّت الحزمة في Wave 0

قرار واعٍ، مُسجَّل كانحراف G9 في تقرير الموجة:

1. **G12 (ميزانية الاعتماديات):** `@sentry/nextjs` يجرّ شجرة كبيرة ويغيّر مخرَج البناء
   ويضيف instrumentation hooks. إضافته في نفس الدفعة مع إصلاح خصوصية تخلط تغييرين
   مختلفَي المخاطر تمامًا.
2. **Definition of Done تشترط `npm run build` ناجحًا.** شحن `import "@sentry/nextjs"`
   بلا تثبيت مُتحقَّق يكسر البناء **للجميع** — ثمن أعلى بكثير من تأجيل الناقل.
3. **الفصل يجعل الوصل لاحقًا يمسّ ملفًا واحدًا.**

## ٣. تركيب Sentry — خطوات خالد

```bash
npm i @sentry/nextjs
npx @sentry/wizard@latest -i nextjs
```

ثم في `lib/observability.ts` أزِل التعليق عن سطر الوصل داخل `captureError()`:
```ts
if (isObservabilityConfigured()) Sentry.captureException(err, { level, tags: safeTags(ctx.tags) });
```

🔒 **أبقِ `pgRedact()` فوقه.** تنقيح Sentry الذاتي allowlist أضعف، **ولا يعرف** أن
رابط PostgREST يحمل قيم الفلاتر — أي بيانات عملاء حقيقية داخل الـURL.

ثم: Vercel → `SENTRY_DSN` لكل بيئة (**قيمة مختلفة لكل بيئة** — أخطاء Preview يجب
ألّا تختلط بأخطاء الإنتاج) → أعِد النشر.

**التحقّق:** أطلق خطأً مقصودًا على Preview، وتأكّد أن الحدث وصل و**أن الـURL والبريد
والـUUID غير ظاهرة فيه**.

## ٤. مراقب التوفّر — خطوة يدوية

خدمة مجانية (UptimeRobot أو ما يعادلها):

| الفحص | المسار | التكرار |
|---|---|---|
| الموقع العام | `https://kianmedia.com/` | ٥ د |
| البوابة | `https://kianmedia.com/client-portal` | ٥ د |

🔒 **لا تراقب مسارات `/api/cron/*`** — محميّة بـ`CRON_SECRET` وسترد ٥٠٠، فينتج تنبيه
كاذب دائم. و❌ **لا تضع أي سرّ في رابط الفحص** (G5): رابط المراقبة يُخزَّن عند طرف ثالث.

## ٥. ماذا يُرصد وماذا لا

**يُرصد:** فشل استقبال النماذج العامة (`PUBLIC_INTAKE_FAILED`) · موافقة لم تُسجَّل
(`PUBLIC_INTAKE_CONSENT_NOT_RECORDED`) · فشل مسارات API الخادمية · أخطاء غير ملتقَطة.

**لا يُرصد عمدًا:**
| البند | لماذا |
|---|---|
| `42501` / رفض RLS | **إجابة صحيحة** لا عطل — رصدها يغرق القناة |
| صفر صفوف | ليست خطأً (`lib/portal/pgerror.ts`) |
| `23P01` تعارض حجز | نتيجة عمل متوقَّعة |
| قيم النماذج | بيانات شخصية — يُرصد الفشل لا محتواه |
