# قبول يدويّ لوحدة المبيعات · CRM manual acceptance

**متى يُنفَّذ:** بعد `PREFLIGHT ← RUNME ← POSTCHECK` وبعد منح المفاتيح.
**من ينفّذه:** المالك، بثلاثة حسابات حقيقية لا بحساب واحد.
**كم يستغرق:** ٤٠–٥٠ دقيقة.

> **قاعدة هذه الوثيقة:** كلّ بند له **نتيجة متوقّعة واحدة** يمكن رؤيتها على
> الشاشة. لا يوجد بند نتيجته «يبدو أنّه يعمل». البند الذي لا تستطيع رؤية نتيجته
> ليس مقبولًا، والبند الذي فشل يُكتب فشله ولا يُلطَّف.

> **لا تجرّب بحساب المالك وحده.** المالك يمرّ من كلّ باب، فالاختبار به يثبت أنّ
> النظام يعمل ولا يثبت أنّه **يمنع**. أخطر خطأ في هذه الوحدة هو منع يبدو قائمًا
> وهو غير قائم.

## ٠) الحسابات الثلاثة

| الرمز | الحساب | المفاتيح |
|---|---|---|
| **م** | المالك (`is_owner` أو `is_admin`) | كلّها ضمنًا |
| **ر** | مدير مبيعات | `crm.view` · `crm.manage` · `crm.manage_targets` · `crm.import` |
| **ظ** | موظّف مبيعات | `crm.view` فقط |

وحساب رابع للتأكّد من الباب المغلق: **ع** = عميل (حساب عميل حقيقيّ، بلا أيّ
مفتاح `crm.*`).

جهّز أيضًا: ملفّ CSV بـ٥ صفوف، منها صفّان بنفس البريد (لاختبار التكرار داخل
الملفّ)، وصفّ بلا `contact_name`.

## ٣) ★ اعتماد المالك على الأهداف — البند الأهمّ

هذا هو البند الذي يجب ألّا تتجاوزه بأيّ حال. **حاملُ المفتاح يقترح، والمالك وحده
يغيّر.**

| # | الخطوة | النتيجة المتوقّعة | ✅/❌ |
|---|---|---|---|
| ٣.١ | **ر** (يملك `crm.manage_targets`): تبويب «الأهداف» → عيّن هدفًا لـ**ظ** | زرّ الحفظ مكتوب عليه **«إرسال لاعتماد المالك»** لا «حفظ» | |
| ٣.٢ | اضغطه | رسالة: «أُرسل الطلب لاعتماد المالك. لم يتغيّر أيّ هدف بعد.» | |
| ٣.٣ | **ظ**: افتح «الأهداف» | **لا هدف جديد** — الطلب المعلَّق ليس تغييرًا | |
| ٣.٤ | **ظ**: افتح خطّ الأنابيب واقرأ «هدفي الحاليّ» | لم يتغيّر شيء | |
| ٣.٥ | **م**: تبويب «اعتماد المالك» | الطلب ظاهر بحالة «بانتظار المالك»، وتظهر **قيمة الهدف المطلوبة** والفترة | |
| ٣.٦ | **م**: اضغط «اعتماد وتطبيق» | «اعتُمد الطلب وطُبِّق التغيير» | |
| ٣.٧ | **ظ**: افتح «الأهداف» الآن | الهدف ظاهر، وشريط الإنجاز يعمل | |
| ٣.٨ | **م**: اضغط «اعتماد وتطبيق» على الطلب نفسه مرّة ثانية | يُرفض بـ«الطلب مبتوت بالفعل» — لا تطبيق مزدوج | |
| ٣.٩ | **ر**: عدّل الهدف نفسه بقيمة أخرى ثمّ **م**: ارفضه | الهدف **لم يتغيّر**، وحالة الطلب «مرفوض» بملاحظتك | |
| ٣.١٠ | **ظ**: افتح تبويب «اعتماد المالك» (إن ظهر له) | يرى **طلباته هو فقط**، ولا زرّ اعتماد لديه | |
| ٣.١١ | **ر**: حاول تعيين هدف **لنفسك** | يُرفض بـ«لا تُحرَّر أهدافك بنفسك» — ولا يُنشأ طلب أصلًا | |
| ٣.١٢ | **م**: عيّن هدفًا لـ**ر** مباشرةً | يُحفظ **فورًا** بلا طلب — المالك لا ينتظر أحدًا | |

**إن نجح ٣.٢ لكن ظهر الهدف عند ٣.٣** فالبند **فاشل**: الطلب صار تغييرًا. أوقف
التشغيل وأبلغ الفريق.

## ٦) ★ استيراد CSV: معاينة قبل الكتابة

| # | الخطوة | النتيجة المتوقّعة | ✅/❌ |
|---|---|---|---|
| ٦.١ | **ر**: تبويب «أدوات» → اختر ملفّ CSV | تظهر **معاينة** بشارة «معاينة — لم يُكتب شيء» | |
| ٦.٢ | افتح «العملاء المحتملون» في تبويب آخر | **لا صفوف جديدة** — المعاينة لم تكتب شيئًا فعلًا | |
| ٦.٣ | اقرأ المجاميع الأربعة | «صفوف الملفّ» = «سيُدرج» + «تكرار قائم» + «صفوف غير صالحة» | |
| ٦.٤ | ابحث عن الصفّ بلا `contact_name` | قراره «صفّ فارغ — يُتخطّى» أو ملاحظته «بلا اسم جهة اتصال» | |
| ٦.٥ | ابحث عن الصفّين بنفس البريد | تحذير أحمر: «مكرّر داخل الملفّ نفسه» — والعدد ظاهر | |
| ٦.٦ | اضغط «إلغاء» | تختفي المعاينة، ولا شيء أُدرج | |
| ٦.٧ | أعد الاختيار ثمّ اضغط **«تنفيذ الاستيراد (ن)»** | تُدرج `ن` صفًّا بالضبط — العدد يطابق ما وعدت به المعاينة | |
| ٦.٨ | ارفع **الملفّ نفسه** مرّة ثانية ونفّذ | «هذه الدفعة مُستوردة سابقًا… لم يُدرج شيء جديد» | |
| ٦.٩ | تحقّق من عدد العملاء المحتملين | لم يزد — الرفع المكرّر لا يُنتج نسخًا | |
| ٦.١٠ | **ظ** (بلا `crm.import`): تبويب «أدوات» | قسم الاستيراد غائب، والنداء المباشر يُرفض من الخادم | |

**٦.٢ هو البند الحاسم.** إن ظهر صفّ واحد بعد المعاينة فالمعاينة ليست معاينة.
