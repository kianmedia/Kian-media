## ٢. النتائج

### 🟠 F-1 — نقطة نهاية Apps Script مكتوبة حرفيًا في الكود

| | |
|---|---|
| **الموقع** | `lib/submitForm.ts` → `SHEETS_ENDPOINT` |
| **ما هي** | رابط Google Apps Script Web App (`/exec`) يستقبل إرسال النماذج العامة |
| **هل هي سرّ؟** | ❌ **لا** بالمعنى الدقيق: تُشحن إلى المتصفح وتظهر في حزمة JS لأي زائر. لا يمكن أن تكون سرًّا بحكم بنيتها |
| **لماذا تُذكر إذن** | (١) نقطة كتابة عامة بلا مصادقة: من يعرفها يستطيع حقن صفوف في الورقة أو إغراقها. (٢) **ثابتة في الكود لا في متغيّر بيئة** ⇒ لا يمكن اختلافها بين Preview وProduction، فكل إرسال تجريبي يذهب إلى **ورقة الإنتاج نفسها**. (٣) تدويرها يحتاج نشرًا جديدًا لا تغيير متغيّر |
| **الخطورة** | متوسطة — سلامة بيانات وتلوّث بيئات، لا تسريب |
| **التوصية** | نقلها إلى متغيّر بيئة `[PV]` ضمن **Wave 1 · V2-1.6** (بند حفظ الـLeads) — ليس إصلاحًا عاجلًا لأنها ليست سرًّا |
| **الحالة** | ⏳ مُبلَّغة، **لم تُغيَّر في Wave 0** (خارج نطاق الموجة، وتغييرها يمسّ مسار الإرسال الحيّ) |

### ✅ F-2 — مفتاح الخدمة خادميّ حصرًا
`SUPABASE_SERVICE_ROLE_KEY` يُقرأ فقط في `lib/server/*` ومسارات `app/api/*`
(`runtime = "nodejs"`). **لا استيراد له في أي مكوّن عميل.** الاستخدام الوحيد بالاسم
الصريح في `/api/public/secure-document` موثَّق بأنه المكان الوحيد المسموح في وحدته.

### ✅ F-3 — التنقيح في السجلّات
`pgRedact()` (`lib/portal/pgerror.ts`) يزيل JWT والمفاتيح والبريد والـUUID والأرقام
الطويلة و**الـURL كاملًا** (رابط PostgREST يحمل قيم الفلاتر = بيانات عملاء).
`lib/observability.ts` (Wave 0) يمرّ عبره إجباريًا قبل أي إخراج.

### ✅ F-4 — الأسرار في الـworkflow الجديد
`.github/workflows/db-backup.yml` يمرّر سلسلة الاتصال **عبر البيئة لا سطر الأوامر**
(`ps` على الـrunner يكشف الوسائط)، و`set -x` **ممنوعة عمدًا**، والـpreflight يطبع
`SUPABASE_DB_URL: Configured` — الاسم والحالة، لا طول ولا بادئة.

### 🟡 F-5 — لا تدوير للمفاتيح موثَّق
لا سجلّ لآخر تدوير لأي مفتاح (Supabase · Zoho · WhatsApp · n8n). لا دليل على تسريب،
لكن **غياب سياسة التدوير نفسه فجوة**. ⏳ توصية: جدول تدوير ضمن الاستقرار.
