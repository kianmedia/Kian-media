«الاختبارات على Preview/Local حصرًا، أبدًا على Production» مستحيل التحقيق.

## ٣. العزل ليس القاعدة وحدها

عزل قاعدة البيانات **وحده لا يكفي**. البيئة معزولة فعليًا فقط حين تُعزل معها
**كل قناة تُحدث أثرًا خارج النظام**:

| القناة | خطر المشاركة |
|---|---|
| Zoho Books | نشرة تجريبية **تُصدر فاتورة حقيقية** |
| WhatsApp | رسالة اختبار **تصل إلى عميل حقيقي** |
| البريد | بريد من **هوية كيان** إلى مستلم حقيقي |
| n8n | أتمتة حقيقية من بيانات وهمية |
| أملاح البصمات | ملح مشترك ⇒ **ربط زائر عبر البيئتين** |

## ٤. خطوات إنشاء بيئة Preview — لخالد

> يحتاج لوحتي Supabase وVercel. **لا أستطيع تنفيذها** (لا صلاحية لوحة تحكم).

### أ) مشروع Supabase جديد
1. Supabase Dashboard → **New project** → اسم مقترح `kian-preview`، **نفس المنطقة**.
2. لا تنسخ أي بيانات إنتاج إليه.
3. Project Settings → API: ستحتاج `URL` و`anon` و`service_role`. ❌ **لا تلصقها في أي ملف أو رسالة.**
4. طبّق المخطط: شغّل حزم `docs/*_RUNME.sql` **بالترتيب** الموثَّق في
   `docs/DATABASE_APPLICATION_STATUS.md` §٤. (على Preview — وهو المكان الوحيد الآمن للتجربة.)

### ب) ربط Vercel — الخطوة التي يُخطأ فيها عادةً
1. Vercel → Settings → **Environment Variables**.
2. لكل متغيّر معلَّم `[PV]` في `.env.example`: تأكّد من وجود **صفّ مستقلّ للـPreview**.
   🔴 **صفّ واحد مُعلَّم بالبيئات الثلاث يعني قاعدة واحدة.** هذا هو الخطأ الشائع.
3. المتغيّرات المعلَّمة `[P]` (Zoho · n8n · `PORTAL_NOTIFY_ENDPOINT`): **اتركها فارغة في Preview**.
4. أعِد نشر الفرع.

### ج) الإثبات — لا تكتفِ بجدول المتغيّرات
اتبع `docs/GATE_A_VERIFICATION_PACK.md` §٤. الاختبار الحاسم هو **(ب) السلوكي**:
سجّل الدخول إلى Preview وافتح قائمة العملاء. **ظهور بيانات حقيقية = البيئتان قاعدة
واحدة**، مهما قال جدول المتغيّرات.

### د) البذر
```bash
KIAN_SEED_TARGET=preview \
SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... \
KIAN_PRODUCTION_SUPABASE_URL=... \
npx tsx scripts/seed-preview.ts --confirm
```
السكربت يرفض العمل ما لم تجتز الحواجز الثلاثة — أهمّها أن الهدف **ليس** عنوان الإنتاج.
