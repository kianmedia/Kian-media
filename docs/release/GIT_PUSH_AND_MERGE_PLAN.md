## ٤. ⚠️ خطر معاينة Vercel — اقرأه قبل أوّل `push`

**ما يُطلق نشر معاينة:** أيّ `push` لفرع مربوط بالمشروع · فتح PR · تحديثه.

🔴 **والمعاينة ليست بيئة معزولة هنا:** تستعمل **نفس متغيّرات البيئة** ما لم
تُفصل صراحةً — أي **نفس قاعدة الإنتاج**. فرابط معاينة يكتب في بيانات حقيقية.

**كيف تتجنّب تسرّب المعاينة إلى الإنتاج:**
- ⛔ لا تشارك رابط معاينة مع عميل.
- تحقّق أنّ الأعلام **OFF** في بيئة المعاينة أيضًا — البناء يدمجها وقت البناء.
- ⛔ ولا تربط دومينًا إنتاجيًّا بنشر معاينة.
- ⚠️ وتذكّر: **`push` لا يعني تشغيل SQL.** الشيفرة الجديدة تتوقّع مخططًا لم
  يُطبَّق بعد ⇒ **مسارات ستفشل على المعاينة**، وهذا **متوقَّع لا عطل**.

## ٥. الفصل بين الدفع وSQL والنشر

| الفعل | يعني | لا يعني |
|---|---|---|
| `push` | حفظ الشيفرة على GitHub | ⛔ **ليس** تشغيل SQL ولا نشرًا للإنتاج |
| تشغيل SQL | تغيير المخطّط | ⛔ **ليس** تفعيل ميزة (الأعلام OFF) |
| Deploy | إتاحة الشيفرة | ⛔ **ليس** تفعيل ميزة |
| رفع علم | إتاحة الميزة للمستخدم | — |

🔴 **ولا يُشغَّل SQL جماعيًّا:** ملفًّا واحدًا في كل مرّة — PREFLIGHT ثمّ قراءة
المخرَج ثمّ RUNME ثمّ POSTCHECK. ⛔ ولا سكربت يشغّل التسعة دفعةً واحدة.
