# قبول الإنتاج — مركز التشغيل والإنتاج

> **الحالة الحالية:** `CODE READY — SQL/PRODUCTION ACCEPTANCE REQUIRED`.
> هذا المستند هو ما يحوّلها إلى «مقبول». **لا أحد غير المالك يوقّع عليه**، ولا
> تُعلَّم خطوة على أنّها ناجحة قبل رؤية النتيجة بالعين.

## 0. ما لا يُقبل كدليل

| ليس دليلًا | الدليل الصحيح |
|---|---|
| «الشاشة فتحت» | صفّ ظهر فعلًا بعد إعادة التحميل |
| «الزرّ مخفيّ عن العميل» | استدعاء PostgREST مباشرةً بجلسة عميل يعيد `not authorized` |
| «الحفظ لم يُظهر خطأً» | قراءة الصفّ من قاعدة البيانات بعد الحفظ |
| «الاختبارات خضراء» | الاختبارات ثابتة (تقرأ الشيفرة) — لا تُثبت سلوك الإنتاج |
| «SELF-TEST مرّ» | يُثبت بنية الحزمة لا سلوك الأدوار: ذاك يحتاج ثلاث جلسات حقيقية |

## 1. ترتيب التشغيل

```
1) docs/operations_center_PREFLIGHT.sql    (قراءة فقط — سجّل النتائج)
2) docs/operations_center_RUNME.sql        (مرّة واحدة؛ آمن عند الإعادة)
3) docs/operations_center_POSTCHECK.sql    (قراءة فقط — قارن بالمتوقّع)
```

**قبل ذلك:** ادفع الكود (`git push`) أوّلًا. الشاشة مصمّمة لتقول
«الميزة بانتظار تفعيل قاعدة البيانات» بدل أن تنكسر، فدفع الكود قبل الـSQL آمن
ومقصود.

### ما يجب أن يظهر في PREFLIGHT

| القسم | المتوقّع | إن خالف |
|---|---|---|
| §1 الاعتمادات الإلزامية | ثلاث `true` + `profiles` موجود | **توقّف** — شغّل الأساس أوّلًا |
| §2 الاعتمادات الاختيارية | أيّ قيمة | غياب `permissions` ⇒ سيعمل المالك/الأدمن فقط |
| §3 عمود اسم المشروع | `project_name` | غيابه ⇒ اسم المشروع سيظهر فارغًا (لا خطأ) |
| §4 لا تصادم | صفر صفّ `prodops%` وصفر جدول `ops_%` | وجودهما ⇒ الحزمة مُشغَّلة سابقًا |
| §5 لقطة التجميد | **احفظ الأرقام الثلاثة** | تُقارن حرفيًّا في POSTCHECK §9 |

### ما يجب أن يظهر عند نهاية RUNME

```
NOTICE:  OPS SELF-TEST: نجح — 20 جدولًا، RLS قراءة فقط، لا anon،
         مُسنَدات لا تعيد NULL، والمنصّة لم تُمَسّ.
COMMIT
```

أيّ `ERROR` يعني أنّ **لا شيء طُبِّق** (كلّ شيء داخل معاملة واحدة). انسخ نصّ
الخطأ كما هو ولا تحاول ترقيعه يدويًّا.

### ما يجب أن يظهر في POSTCHECK

| § | المتوقّع حرفيًّا |
|---|---|
| 1 | ٢٠ صفًّا، `present = true` و`rls = true` في كلّها |
| 2 | **صفر صفّ** (لا سياسة كتابة مباشرة) |
| 3 | **صفر صفّ** في الاستعلامين (لا صلاحية anon) |
| 4 | كلّ الصفوف `security_definer = true` و`pinned_search_path = true` |
| 5 | `false` في كلّ صفّ (الدوالّ الداخلية غير منفَّذة من الواجهة) |
| 6 | صفّ واحد، كلّ الأعمدة `false` — **ولا واحد `NULL`** |
| 7 | `ok:true` · `can_view:false` · `authenticated:false` |
| 8 | ٨ صفوف (أو صفر إن كان الكتالوج غير مطبَّق) |
| 9 | **صفر صفّ**، والأرقام الثلاثة **مطابقة** لـPREFLIGHT §5، و`confdeltype = n` |
| 10 | القيد يذكر `manual`/`placeholder` فقط |
| 11 | صفّ واحد |
| 12 | أصفار |
| 13 | ٦ صفوف `present = true` |
| 14 | `true` (7B سليمة) |
| 15 | ٣ صفوف مُشغِّلات، `tgenabled` ≠ `'D'`، و`fires_on_insert`/`fires_on_update` كلاهما `true`؛ ثمّ ٣ صفوف `raises_distinct_code = true`؛ ثمّ صفّ واحد بكلّ الأعمدة `NULL`؛ ثمّ **صفر صفّ** (لا حارس مكشوف للواجهة) |
| 16 | صفّ واحد، الأعمدة الثلاثة `true` |

> `tgenabled = 'D'` في §15 يعني أنّ أحدهم عطّل حارس الحجز المزدوج: الازدواج صار
> ممكنًا من كلّ مسار. هذا وحده يوقف القبول.

## 2. اختبار القبول الحيّ — ثلاث جلسات، ثلاثة متصفّحات

> **لا تُجرَ بحساب واحد.** التبديل بين الأدوار في نفس المتصفّح يُبقي جلسة
> قديمة أحيانًا ويعطي نتيجة كاذبة. استعمل نافذة خاصّة لكلّ دور.

### التحضير (بحساب المالك)

1. شاشة الصلاحيات ← امنح مهنة «مدير تشغيل» (أو موظّفًا بعينه) المفتاح
   `operations.manage`.
2. تأكّد أنّ لديك: حساب مدير تشغيل، حساب مصوّر (طاقم)، حساب مونتير، حساب عميل.

### أ) المالك / مدير التشغيل

| # | الخطوة | القبول |
|---|---|---|
| A1 | افتح «التشغيل والإنتاج» | تظهر ٦ تبويبات، وأوّلها «لوحة اليوم» |
| A2 | المواقع ← «+ موقع» (اسم + مسؤول + جوّال) | يظهر الموقع بعد الحفظ، والجوّال قابل للنقر |
| A3 | أوامر العمل ← «+ أمر عمل» (عنوان + نوع + بداية + نهاية + الموقع) | يُنشأ برمز `OPS-YYMM-####` |
| A4 | افتح المهمّة ← الطاقم ← أضف المصوّر | يظهر الصفّ، وتصل المصوّر إشعارًا داخل البوابة |
| A5 | المعدّات ← أضف كاميرا (نافذة زمنية) | يظهر الصفّ بحالة «مطلوب» |
| A6 | التصاريح ← أضف تصريحًا «قيد الإعداد» | يهبط شريط الجاهزية |
| A7 | السلامة ← «بذر القائمة» | تظهر ١٠ بنود عربية |
| A8 | Call Sheet ← أضف ← «نشر» | تتحوّل إلى «منشورة»؛ محاولة تعديلها تُردّ برسالة «منشورة — أنشئ نسخة جديدة» |
| A9 | الحالة ← «مجدولة» ← «مؤكّدة» | ينتقل؛ ومحاولة القفز من «مسوّدة» إلى «منتهية» تُردّ بـ«انتقال غير مسموح» |
| A10 | أنشئ مهمّة ثانية بنفس الموقع ونفس الوقت وبنفس المصوّر | تبويب «التعارضات» يُظهر **شخص محجوز مرّتين** و**تعارض موقع** |
| A11 | لوحة اليوم | العدّادات تطابق ما أنشأته؛ النقر على عدّاد يفتح قائمته |
| A12 | بطاقات الذاكرة ← أضف بطاقة ← اضغط «تحقُّق» قبل النسختين | يُردّ: «لا يُعلَّم التحقّق قبل تسجيل نسختين فعليًّا» |
| A13 | اضغط «نسخة أولى» ثمّ «نسخة ثانية» ثمّ «تحقُّق» | يُقبل، وحالة البطاقة تصير «مُتحقَّق منها» |

### ب) فرد الطاقم (المصوّر)

| # | الخطوة | القبول |
|---|---|---|
| B1 | افتح البوابة | تبويب «مهامّي الميدانية» موجود، وهو **الأوّل** |
| B2 | «مهامّي» | تظهر المهمّة المُسندة فقط — لا مهامّ الآخرين |
| B3 | افتح المهمّة | لا يظهر «تعديل» بجانب أيّ صفّ، ولا زرّ «+ إضافة» |
| B4 | «أؤكّد الحضور» | تتغيّر الحالة إلى «أكّدت» فورًا |
| B5 | التقرير اليوميّ ← اكتب ← «حفظ كمسوّدة» ← «إرسال» | يُحفظ ثمّ يُرسل؛ وبعد الإرسال تظهر «تقريرك مُرسَل ولا يُعدَّل» |
| B6 | تبويب «أوامر العمل» | يظهر فقط ما هو مُسنَد إليه |
| B7 | الصق رابط مهمّة **غير** مُسندة إليه | «لا تملك صلاحية» — لا شاشة فارغة ولا «ترحيلة ناقصة» |

### ج) المونتير

| # | الخطوة | القبول |
|---|---|---|
| C1 | (بحساب المدير) أنشئ «تسليم ما بعد الإنتاج» للمونتير | يظهر الصفّ |
| C2 | افتح بوابة المونتير ← «مهامّي» | يظهر التسليم تحت «أعمال ما بعد الإنتاج المُسندة إليّ» |
| C3 | اضغط «استلمت» ثمّ «قيد العمل» ثمّ «أنجزت» | تتغيّر الحالة في كلّ مرّة |
| C4 | داخل المهمّة | لا يرى تسليم مونتير آخر، ولا تقارير غيره |

### د) العميل — **الاختبار الحاسم**

| # | الخطوة | القبول |
|---|---|---|
| D1 | افتح بوابة العميل | **لا يوجد** تبويب مركز تشغيل |
| D2 | الصق `/client-portal/operations` مباشرةً | شاشة «لا تملك صلاحية» — وليست «بانتظار تفعيل قاعدة البيانات» |
| D3 | من أدوات المطوّر، نادِ `rpc/prodops_jobs_list` بجلسة العميل | استجابة خطأ `not authorized` |
| D4 | نادِ `rpc/prodops_access` بجلسة العميل | ينجح ويعيد `can_view:false` — ولا يعيد أيّ بيانات مهامّ |
| D5 | نادِ `/rest/v1/ops_jobs?select=*` بجلسة العميل | **مصفوفة فارغة** (RLS) — لا صفّ واحد |
| D6 | نادِ نفس المسار بمفتاح `anon` بلا جلسة | رفض صلاحية — لا بيانات |

> **إن نجح D5 في إعادة صفّ واحد فالقبول يتوقّف فورًا.** هذا هو نمط الحادثة
> السابقة (قراءة بيانات شركة بمفتاح anon) ولا يُتسامح معه.

## 4. التدقيق

بعد الجولة كاملةً، بحساب المالك:

```sql
select action, entity_type, count(*)
from public.ops_audit
group by 1,2 order by 3 desc;
```

**المتوقّع:** صفوف لـ`job_create` · `job_update` · `job_status` · `child_upsert`
· `attendance` · `daily_report` · `backup_step` · `call_sheet_publish`
· `post_handoff_progress`. **غياب أيّ منها بعد تنفيذه = عطل قبول.**

```sql
select actor_id, action, at from public.ops_audit order by at desc limit 20;
```

**المتوقّع:** `actor_id` يطابق من نفّذ فعلًا (لا NULL، ولا هويّة المالك عن فعل
الموظّف).

## 6. حدود معروفة تُقبل مع الموديول (لا تُكتشف لاحقًا كمفاجأة)

1. **حجز المعدّة هنا لا يخصم من المخزون.** التعارض يُكشف، والحركة الفعلية تبقى
   في موديول العهدة. الربط بالمرجع يدويّ اليوم.
2. **الطقس إدخال يدويّ.** لا خدمة خارجية ولا تحديث تلقائيّ.
3. **ستّة مفاتيح صلاحيات مسجَّلة وغير مفحوصة بعد** (انظر مصفوفة الأدوار §2).
   منحها لا يغيّر شيئًا اليوم.
4. **لا توليد ملفّ PDF للـCall Sheet.** الورقة صفحة HTML مهيّأة للطباعة
   (`@media print`، أسود على أبيض، صفر مورد خارجيّ) وتُطبع من المتصفّح.
7. **الحرّاس لا يُصحّحون الماضي.** مُشغِّلات منع الحجز المزدوج تفحص ما يُكتب
   بعد تركيبها. أيّ ازدواج كُتب قبلها يبقى ويظهر في تبويب التعارضات، وأوّل
   تعديل يمسّه سيُرفض. راجعه بالاستعلام في نهاية PREFLIGHT.
8. **المسوّدة لا تحجز.** الحجز المزدوج يُمنع عند الالتزام بالحالة فقط. مسوّدتان
   متداخلتان مسموحتان، وأوّل جدولة منهما ستُرفض إن بقي التداخل.
5. **الإشعار داخل البوابة فقط.** لا بريد ولا واتساب من هذا الموديول.
6. **`prodops_visible_jobs()` تُقيّم لكلّ صفّ.** مقبول عند مئات المهامّ؛ يُعاد
   النظر إن تجاوزت الآلاف.
